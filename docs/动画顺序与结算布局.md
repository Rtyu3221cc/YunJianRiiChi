# 动画顺序与结算布局（Unity 0.5.23）

本次对照拔北、和牌及结算截图、《荒牌流局.mp4》和《自己荣和.mp4》，继续使用一姬立绘、原版结果字图、麻将牌面和火龙卷 305034。

## 显示和动画

每个座位的拔北牌都放在自身左侧，局部旋转统一为 90 度，再随座位转换到牌桌坐标。对手和牌后的重建保留自己的相机手牌；自己的手牌在实际亮牌开始后才淡出。火龙卷原版网格沿水平面朝向当前相机，避免侧边玩家的柱面贴图变成薄片。

放倒动作依录像分成预备、加速、触桌轻微过冲和回弹稳定，共 0.58 秒；这是本项目对录像运动的曲线适配，并非声称原安装包的时序代码被逐字复制。原版粒子资源、音效和一姬报役保持不变。

公开动作按照事件序号播放。同一事件的手部和提示同时启动，不同事件在当前动作结束后才启动。开局理牌期间不启动后续动作；操作按钮及提交也等待待播事件清空。下一次自己的摸牌在前一个出牌/立直动作完成前暂不显示。非本回合仍可预选手牌。

## 结算和弹框

结算背景扩展到实际屏幕边缘，内容继续按安全区域缩放。标题根据点数字图的实际宽度排在点数前，保留 124 虚拟像素的原字图高度；三倍役满、四倍役满等长标题只左移，不缩小。

吃牌框沿用原来的横向间距，小牌组在框内上移，底边留空。听牌框保持牌与张数底牌的间距；金边花纹和深蓝底分层，派生 `pop_frame` 去掉原框内部半透明蓝色像素，避免九宫格重叠产生横线。原始 `pop_bound` 保留，派生过程及哈希见 Indicators/source.json。

## 预览与验证范围

十二张结算截图覆盖普通和牌、满贯、跳满、倍满、三倍满、累计役满及一至六倍役满，均由实际 Unity 客户端在 754×347 尺寸渲染。预览局面为验证用合成数据，点数与标题用来展示排版，不代表各角色牌例的真实计分结果。

自动检查覆盖失去手牌的状态切换、四个座位拔北位置、四向特效相机朝向、事件先后与按钮解锁，以及既有规则、音效和布局回归。安卓真机触摸、听感和热点联机未执行。
