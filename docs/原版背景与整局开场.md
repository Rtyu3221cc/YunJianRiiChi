# 原版背景与整局开场（Unity 0.5.24）

对照用户指定的结算背景图片与四人对阵画面，并核对用户 APK 的 UI_Win、UI_FightBegin 预制体和固定版本雀魂代码。所有资源离线打包，仍使用一姬立绘。

## 结算背景

APK 主背景是 `bg_jiesuan1`，1433×781，与用户最后提供的背景一致；UI_Win 还使用 `bg_jiesuan`，512×288，作为透明度0.4的底层。原始大图节点矩形为1433×792，统一缩放1.885179倍并向上偏移198原生坐标单位。当前实现沿用这套矩形和相对位置，按窗口等比扩展背景层并裁切；内容仍使用原来的安全区域坐标。资源查证显示两层背景结构，不能把它描述成每个屏幕比例都有独立图片。

预览检查16:9、936×435宽屏、774×438参考比例和1024×768的4:3屏幕。宽度与高度共用缩放因子，不为每个尺寸分别拉伸斜边与花纹。

## 役满等级火焰

原版 UI_Win 在等级标题出现300ms后调用 `effect_yiman.lh` 或 `effect_yiman2.lh`。单倍役满使用前者；累计役满与多倍役满使用更宽的后者。两套都包含六个发射器：主体火焰、持续火星、上升火焰、爆发火星、爆发火焰和闪光。保留原平面网格、4×4火焰帧图、粒子数量/速度/大小/透明度、黄橙红RGB渐变及横向盒形发射器。三倍满及以下不启动这个效果。

标题字图保持原尺寸，长标题仍避开点数。火焰绑定当前标题位置；确认、换和牌者、返回大厅与后台时清理特效。原有一姬报役和等级声音不变。

## 整局开场

UI_FightBegin 原版四向 `start_down/start_right/start_up/start_left` 画框、`namebg`、`myself`、胜负粒子与花瓣资源用于开场。一姬立绘按原预制体位置和方向裁切到画框中，姓名从房间公开玩家列表读取；项目未提供段位/称号数据，因此不虚构段位标识。动画保留500ms预备、400ms strongIn滑入、700ms胜负声音、1200ms胜负/花瓣出现、400ms离场和淡出阶段。

新增公开 `matchSeq/matchStartedAt` 区分整局与 `handSeq/dealtAt` 小局字段。开场结束再开始已有发牌/理牌动作；主机AI在新整局的前6秒等待，不会在开场界面背后先打牌。从已观察到的大厅/上一整局切换到新整局时，以房间编号变化为依据，不要求各手机时钟同步。每个房间整局编号在客户端内存与本机偏好中去重，轮询和已播放的重连不重播；下一小局保留同一整局编号，整局结束后再开增加编号。三人局隐藏未占用的上方格子，四人局显示全部玩家。

## 来源与验证范围

背景、四向画框、姓名底纹和可匹配的特效贴图直接从用户提供的雀魂4.0.16 APK导出。APK粒子预制体对应场景的原参数、网格和少数缺失贴图由雀魂官方固定版本资源补充；不是游戏运行时联网下载。资源路径、对象编号、转换方式和SHA-256分别保存在 Results/source.json、MatchIntro/source.json 与 UiEffects/source.json。

验证包括80项规则/公开协议检查、完整Unity回归、三四人开场、下一小局/轮询/重连去重、新整局再播放、发牌与操作按钮等待、四种屏幕比例，以及累计役满至六倍役满火焰。截图是实际Unity渲染的合成公开局面，用于检查排版和素材；不是规则计分案例。安卓真机触摸、听感、不同手机性能和热点联机未执行。
