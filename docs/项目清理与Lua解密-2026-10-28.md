## 解密结果

成功恢复了本机 `dist/Majsoul_4.0.16_MC.apk` 中以下五份输入相关脚本：

| 文件 | 解密后字节数 | 整理后行数 |
|---|---:|---:|
| hand.lua | 2,035 | 87 |
| handpai3d.lua | 7,049 | 252 |
| handpaiplane.lua | 13,048 | 506 |
| mjpai.lua | 2,750 | 214 |
| viewplayer_me.lua | 38,280 | 1,893 |

原始载荷的处理链已确定为 Base64 → AES-128-CBC／PKCS7 → UTF-8，并有 BOM／尾部控制字符整理。实际类为 `StringObfuscator`，解密函数 RVA 为 `0x21546bc`，初始化函数为 `0x2155b28`。16 字节 Key／IV 从经过 SHA-256 校验的 IL2CPP 元数据初始化字段提取，研究报告和游戏资源不保存其明文值。

五份结果都通过了 PKCS7、严格 UTF-8 和重新加密逐字节还原原密文的检查。整理后的源码还分别通过 LuaJIT 语法解析，并与原始解密文本保持相同 AST；只增加空白和缩进，没有执行原版 Lua。原版已经压缩了注释和部分局部变量名，这部分不能凭空恢复。

原始解密文本：`build/lua-reverse-20261028/decrypted/`。

可读版本：`build/lua-reverse-20261028/decrypted/readable/`。

检查记录：`decryption-checks.json`、`syntax-checks.json`、上级目录的 `crypto-evidence.json` 和 `summary.json`。保留了相关类声明及带名称注释的 ARM64 反汇编，完整的大型临时转储已移除。

## 已确认的原版拖动行为

以下行号对应可读版本 `viewplayer_me.lua`：

- **启动阈值**：第 1338～1342 行，屏幕坐标位移平方大于 400，即距离大于 20 个屏幕像素后进入拖动。
- **松手出牌**：第 1308～1320 行，需要允许出牌、松手点位于手牌区域之外、当前牌有效，并通过该模式的 `baida` 限制。
- **手牌区域**：第 57～69、1166～1211 行，用手牌模板的实际相机投影计算 Y 边界，`inHandRange` 由指针 Y 坐标与该边界比较得到。
- **拖动排序**：第 1356～1378 行，在允许的状态下，手牌区域内横向拖动会调整牌的顺序；拖动牌使用屏幕坐标转世界坐标跟随指针。
- **按下选牌**：第 1269～1299 行，按下时就记录所选牌及按下坐标；再次点到已选择的牌，松手时按合法性判定出牌。

当前 0.6.17 使用的是按用户描述实现的中央矩形出牌区、与手牌高度相关的拖动启动阈值，以及原顺序归位。原版使用手牌 Y 边界、20 像素启动阈值，并包含手内拖动排序。若后续对齐原版，需要按这些实际源码修改，同时保留云间日麻已有的轮询、重复牌身份及失焦取消处理。

## 复现

```powershell
python -X utf8 scripts/recover-majsoul-input-lua.py
node scripts/format-recovered-lua.cjs
```

恢复脚本直接读取本地原始 APK 和已固定的元数据字段，不需要保留原生库解包副本，也不运行或登录原版游戏。

静态解析使用 [Il2CppDumper 官方项目](https://github.com/Perfare/Il2CppDumper) 的 v6.7.46，语法校验使用 [luaparse 官方项目](https://github.com/fstirlitz/luaparse) 的固定提交版本。工具来源与摘要在本地分析目录及 `tools/lua-parser-local/provenance.json` 中记录；这些引用仅说明分析工具来源，原版具体行为以本机恢复的源码和校验记录为证。
