# 云间日麻 Unity 0.6.7 交接

版本号 0.6.7，versionCode 55；原包名 `com.yunjian.riichi.unity` 和签名证书保留。

## 资源范围

当前固定输入目录共有 **122 名角色、486 套服饰、69 套动态服饰**。本次补充其余 109 名角色，并把寺崎千穗理扩展到完整五套服饰；其他已发布角色复用原资源版本。角色语音、数字表情、三种必需立绘以及多层动态骨骼一起整理。

一姬、二阶堂美树完整内置且不可删除，其余资源保持按需下载。APK 包含轻量头像和元数据，不把全部可选媒体塞进安装包。“部分下载”仍选择原来的女性 TOP10＋汪次郎，其他角色从“全部下载”或自选列表进入。

当前 Android 全部可选资源为 **2,363,202,402 字节（约 2.36 GB）**；热门角色中需要额外下载的资源为 **230,960,457 字节（约 231 MB）**。这是独立资源大小，另加 APK 和运行缓存。

角色资源发布页：<https://github.com/Rtyu3221cc/YunJianRiiChi/releases/tag/character-resources-v2>。目录引用不可变的版本文件，未变化的角色继续使用 v1 Release 地址；旧 APK 的地址不被覆盖。

## 本轮客户端变化

资源界面使用原字体与细表情边框；去除下载对勾，条目恢复原间距。定位描边加粗，与滚动条分开，关闭独立窗口、退出设置或切换页签后清除。删除标题下方冗余说明，上移按钮，设置页完整显示四行角色；独立窗口列表扩展到底部，说明和关闭按钮共用底栏。

全量包新增 LZ4 分块格式，安装和启动校验完成后释放临时加载对象；实际资源按需打开。客户端对不在当前画面使用且未被对局／传输引用的缓存做限制，动态渲染缓存也限制历史服饰数量。基础角色保护、下载校验、续传、删除后偏好清理，以及房间资源准备与一姬替代继续保留。

全部角色安装后，排序界面按每行八张头像换行，支持滚动、滚动条拖动和拖动排序时的边缘滚动；避免全量头像向屏幕右侧溢出。

## 更新工具与说明

完整维护文档见 [新增角色与皮肤维护指南](character-resource-maintenance.md)，包括输入合并、单角色准备、分层骨骼、构图、包版本、两平台构建、验证、不可变附件和客户端发布。

新增入口：`merge-character-inputs.py`、`sync-character-registry.cjs`、`character-packs.py`、`verify-character-packs.py`、`fetch-character-pack-cache.py`、`release-project.py`。`prepare-character-resources.py` 支持 `--all`、`--roles`、`--force` 与 `--web-only`。版本号和 versionCode 由 `ProjectSetup.cs` 集中管理。

大型新增原始媒体不重复提交到 Git 历史，可通过版本输入快照重建；源码提交保留原来已跟踪的参考角色素材，并提交所有新角色元数据、轻量头像、输入快照、构建／验证工具及说明。运行所需媒体以 GitHub Release 的独立资源包分发。

## 验证依据与限制

实际结果、每个资源包的大小／SHA-256、完整角色加载／渲染结果，以及 APK 签名摘要见同版本 `unity-0.6.7-verification.json`。单元检查覆盖房间规则和资源目录；输入合并另有测试。两个平台分别核对 bundle 内容，Windows 编辑器实际读取图片、骨骼、语音和表情；下载、取消、续传、坏包、删除保护、批量下载、房间等待与本机一姬替代通过真实 HTTP 服务验证。

本轮通过：149 项 Node 单元、8 项输入合并单元、571 项既有 Unity 断言、25,713 项完整资源断言、244 个双平台包内容检查、43 项资源与房间流程、15 项资源窗口布局检查。所有角色的表情引用去重并逐项加载验证；语音共 17,992 段。全角色排序验证包括多行星标、末页可达、当前可见头像保留及上一页未引用头像释放；完整截图见 `dist/previews/unity-0.6.7-resources/`。

发布检查包括原证书、v1/v2、API23 独立 v1、ZIP 完整性、16KB 对齐和发布 ZIP 内 APK 的大小／摘要一致；GitHub 附件只核对服务端大小和摘要，不为重复验证而回下载。

**未完成 Android 真机安装、触摸、声音、后台传输、低内存设备及多手机热点验证。** 编辑器中的局域网源与中转在同一台机器上运行，其他房间成员由测试请求模拟。当前客户端使用内置可信目录；加入新角色或皮肤后需要新 APK，不是远程自动发现目录。
