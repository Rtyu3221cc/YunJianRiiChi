# 装扮预览音效修正

用户反馈：0.6.33 的「和牌－神火坠霄」在装扮预览中仍无音效，实际和牌尚未测试。本轮定位到预览流程的问题，并修正所有共用该流程的和牌、立直等牌桌预览。

## 原因

`GameAudio.Cue()` 仅在牌桌音效通道启用时接受请求。实际对局的 `ApplyRoomState()` 会调用 `gameAudio.SetScene()`；装扮预览的 `PlayDressIntro()` 和 `ShowDressPreviewState()` 原先只更新入场动画、牌桌和特效，没有同步音效场景。因此 `inTable=false`，即使音档存在、音量开启，也会在加载音档前拒绝播放。

上轮验证独立调用 GameAudio 前手动启用了牌桌通道，证明了音档与播放 API 可用，但未覆盖真正的装扮预览入口。这是上轮漏掉的检查，0.6.33 的 APK 资源完整不等于预览流程有声。

## 修改

- `RiichiClient.DressPreview.cs`：预览入场及脚本状态更新时同步音效场景。沿用用户的音效开关与音量，预览仍不连接房间。
- `LobbyController.DressTable.cs`：轮换座位前等待音效声道结束，避免循环重置场景时截断较长音效。主动关闭预览仍立即停止。
- 本轮没有重新下载、替换音档或修改角色语音、计分规则和公开资源目录。

## 实际预览验证

使用已校验的 Windows 装扮包，从真实装扮预览入口运行。没有直接调用 Cue 作为预览成功的依据；同时记录实际特效出现、通道状态、AudioSource.isPlaying 和 GetOutputData 音效声道输出。
