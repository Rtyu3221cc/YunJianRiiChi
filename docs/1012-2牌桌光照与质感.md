# 1012-2 牌桌光照与质感

参考：`D:/MyWorkSpace/video/1012-2` 的雀魂原版截图、批注图和当前效果截图。工作目录为 `YunJianRiichi_Claude`，未修改 Codex 工作区。

## 质感差异的原因

当前版本的麻将牌面使用无光照着色器，牌身亮度是按估算法线做的柔和渐变，桌面只有平铺的布纹。雀魂 `scene_mj.prefab` 中，牌桌质感来自下面四项，均已从 APK 读取：

| 项目 | APK 原始数据 | 本次实现 |
| --- | --- | --- |
| 牌的光照 | `scene_mj/light` 方向光（旋转 (0, .5251, -.8510, 0)）；`mjp_face` / `mjp_mid` 使用 `Catfood/Cartoon_nonoutline(_tile_back)`，`_SplitThreshold` .08，`_ColorLight` 1，`_ColorUnlight` .8113 | 从 shader `compressedBlob` 解出 GLES3 片元程序，逐项移植到 `OriginalTileFace` / `OriginalTileBody`。只用光的方向，不用光色与强度（原程序同样如此）。朝上的牌面全亮，朝向玩家的侧面为 .81，中间 0.1 宽的过渡带线性混合 |
| 牌身贴图 | `mjp_mid`：`_MainTex` 为牌背皮肤，`_TileTex` 为牌面图集最右一列（scale .1，offset .9），按牌背 alpha 混合 | 替换原先“按高度切换牌背 / 固定纸色”的估算 |
| 描边 | `Catfood/Outline` 片元直接输出材质 `_Tint` (.165, .192, .204) | 旧版读取了该 shader 不使用的 `_OutlineColor` (.283)；已改为 `_Tint` |
| 牌下阴影 | `mjp_new/effect_shadow`：`shadow.png`（32×32，alpha .5，软边），`Catfood/Additive Transparent`，renderQueue 3002；网页版代码按 `.53 × PAIMODEL_WIDTH/HEIGHT` 缩放 2.54 单位平面 | 每张桌面牌、竖立暗牌使用原贴图，覆盖约 1.41 × 1.40 牌宽／牌长，居中；替换 24% 纯黑圆角块 |
| 光束与浮尘 | `room/sun_shine` 三个加色粒子（`yuanqiu2`，长条 billboard 约 −45°，透明度 .03–.08，寿命 10–20 秒） | 按原序列化模块整体导入为 `TableLook/sun_shine` prefab；场景坐标按 (−x, y, −z) × 11.195 换算，粒子缩放改为 Hierarchy |

坐标换算与既有拔北锚点一致。光的朝向向量换算后为 (0, .894, .448)。

## 批注项

1. **左上房间文字底部**：使用 `container_lefttop/gamemode` 的 `bg_type` 渐变底，原矩形 (23,186,290,51)；文字颜色改为原 `lb_mode` 的 (.91,.686,.443)。
2. **名称字号与称号**：`container_name` 为 180×30 × .9，字号 32 × .7 × .9；按牌桌 HUD 统一的 .55 换算后约 89×15、11 号字。旧版约大 1.5 倍。“暂无称号”改用官方资源 `extendRes/title/notitle.png`（APK 内不含称号图片；CDN 文件为 XOR 0x49，导入时校验 SHA-256）。
3. **牌河凌乱**：网页版 `code.js` 的字符串表混淆无法完整还原，未找到可直接照抄的随机代码。按参考图测量，把位置扰动调整为横向 ±.010、纵向 ±.014、偏转 ±2°（旧版 ±.005 / ±.012 / ±1.2°）；仍按座位、弃牌序号和局数稳定生成。这一项是参考图拟合，不是原代码。
4. **吃碰杠胡拔北按钮位置**：按 `UI_ChiPengHu` / `UI_LiqiZimo` 的 `container_btns`（中心偏移 (−317, −230)，缩放 .7，384×186 按钮，pivot (.5, .2)）从右向左排列，画布按 1920×1080 Expand 换算。吃牌组合框与按钮行右对齐，位于其上方。有可选操作时不再在同一位置显示“请选择操作”。

## 桌布

APK 不包含桌布与桌面网格，运行时材质未知。两张参考图同分辨率同视角，逐像素比较桌布区域的亮度中位数：原版约为当前的 .92（R .914、G .935、B .955），中央略亮。`TableCloth` 增益由 1.1 改为 (1.005, 1.029, 1.051)。这是参考图拟合值。

## 预览纹理渲染时机

宝牌栏、结算宝牌和吃牌／听牌小麻将原先在 `OnGUI` 中首次调用 `Camera.Render()`。加入 `sun_shine` 后，GUI 阶段显示的宝牌栏变成未渲染的青色目标。现在手牌小图在 `TableRenderer.Awake` 预先渲染 38 张，宝牌／里宝牌与反光在 `LateUpdate` 渲染；`OnGUI` 只读取缓存。

## 0.5.29 复核修正

按 0.5.28 实机截图的批注：

1. **房间文字裁切**：毛笔字体的字形高于行框，原 23 px 高的裁切框切掉了字顶。文字改为在整条 `bg_type` 底图内居中，并关闭裁切。
2. **同类牌指示**：0.5.28 的卡通明暗只给牌面受光部分染蓝，牌身受光的白边未染色，看起来像贴了一块蓝色贴纸。现在先按原程序计算明暗，最后对牌面、牌身和描边统一乘一次原版蓝色 (.615, .827, .976)。
3. **牌河错落**：幅度由 ±.010 / ±.014 / ±2.0° 调为 ±.007 / ±.010 / ±1.4°（约为 0.5.28 的 70%，仍大于 0.5.26 的 ±.005 / ±.012 / ±1.2°）。
4. **拔北牌尺寸**：对比投影后的牌面大小（顶面投影面积的平方根，不受透视倾斜和座位朝向影响），每张北牌缩小到不超过自家副露牌面，若该座位副露更小，则不超过该座位副露。只缩不放。自家副露以贴底缩放后的实际显示为准。拔北动作中搬运的北牌同步缩放，落牌时不会跳变。
5. **点击樱花**：采用雀魂网页版默认点击特效 `scene/effect_click_default.lh`（官方 CDN）：一层 4×5 樱花序列帧花瓣，每次按下爆发 12 片（原为 6～12 片，本工程与其他导入特效一样取最大值），寿命 0.5～1.4 秒，低重力飘散并淡入淡出；另有一层 0.2 秒的粉色 `gaoliang` 闪光。花瓣贴图为 APK `myassets/necessary/texture/yinghua.png`，闪光为 APK `myassets/common3d/texture/shanguang.png`，平面网格取自 CDN `plane1X1-Plane01.lm`。原场景 `scene_click_effect.ls` 使用高 18 单位的正交相机，本工程照此设置，在 GUI 最后渲染，因此花瓣位于按钮与 HUD 之上。导入脚本为 `scripts/import-click-effect.py`，来源记录在 `UiEffects/click-source.json`。APK 中的 `common3d/prefab/yinghua2.prefab` 是大厅循环飘落的花瓣，不是点击特效，未采用。
6. **过期检查**：`ValidateNorthEffects` 改为 0.5.25 之后的行为。拔北使用较短的出牌动作，在落牌前采样手部，落地时不产生樱花。
