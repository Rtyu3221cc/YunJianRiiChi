# 表情互动与随机形象冷加载修复：0.6.10

日期：2026-10-23。Android versionCode 58，原包名 `com.yunjian.riichi.unity`，原签名证书；本地实测包，未发布至 GitHub。

## 修改

- 收起的表情入口整体放大 20%，包括背景、笑脸和点击区域；金色边框继续贴齐屏幕右侧。展开面板和收起箭头沿用已确认的位置。
- 电脑表情由房主房间引擎统一调度。每个电脑有 30% 概率回应真人发出的表情，计划延迟为 1200～1700ms；选取该电脑本局冻结角色拥有的基础表情。保留五秒冷却，每个电脑最多排队一条，不因电脑回应再次触发回应。重复请求不重复排队，结算、换局和长时间暂停后的过期任务会取消；调度存档失败会回滚。
- 下载资源确认弹窗的“返回”和“开始下载”统一为其他原版弹窗的 316.87 × 87.5 设计尺寸和 42 号字体。
- 随机电脑形象默认开启。由于旧版会把关闭默认值写入设置，本次通过 `riichi.setting.randomBotDefaultVersion` 做一次默认值迁移；之后手动关闭继续持久保存。候选仍仅来自房主已安装角色及各角色已选服饰。
- 房间卡片改用异步资源入口。首载显示角色头像与“形象加载中…”提示，完成后用 180ms 淡入原有立绘构图。牌桌头像改为异步读取，开局立绘、专用卡片、正反向图与语音预加载也改为异步队列，完成前不报告资源准备完成。队列加载期间降低 Unity 后台整合优先级，已加载资源直接复用缓存。

## 雀魂代码依据

参考已有 APK 提取代码 `build/character-review-r2/code-readable.js` 中的 `Desktop.showAIEmo`：每个 AI 以 0.3 概率回应，原延迟为 `500 + 1000 * Math.random()`，原基础表情选择范围为 0～8。这里沿用其概率与基础表情策略，延迟按用户要求调整；同时由单个房主统一安排。

本次摘录和来源摘要保存在 `build/interaction-070/reference/`，未把测试用固定随机数放进游戏运行资源。

## 验证

- Node：162 项全部通过，包含新增的延迟边界、跳过回应、角色身份、不连锁刷屏、重启恢复、保存失败回滚、换局与过期取消测试。
- Unity 实际运行：7 项检查全部通过。测试房间固定随机数以展示四向气泡，三个电脑回应耗时均为 1287ms；正式游戏仍按 30% 概率回应。
- 三个首次加载的可选角色：0 次同步包加载，3 次异步包加载。加载提示、最终构图、设置默认值、两个按钮和表情互动均已生成实际截图。
- 冷场景加首轮资源预热的 Windows 编辑器观测峰值帧耗时为 148.5ms，包含房间首次显示；预热约 7.27 秒。这个记录不等同于手机帧率，不能据此声称所有设备都不会出现单帧抖动。实际证据为 `build/interaction-070/render/checks.json`。
- APK：原证书、v1/v2、API23 独立 v1、16KB 对齐、ZIP 完整性、当前手机房主引擎、ARM64/ARMv7 与资源检查通过。手机冷载、触摸和多手机交互留待新包实测。
