### 已实现的使用逻辑

- 未下载角色在宿舍有轻量头像和黑色遮罩；点击可进入对应角色的下载提示／资源管理位置。
- 启动时可选择全部下载、部分下载或暂不下载；设置中有资源管理页。
- 下载包括 SHA-256／大小校验、进度、取消、续传和坏包拒绝。
- 只有安装了资源的角色才出现在出战切换和随机候选中；删除会清理相关出战、星标和随机候选。
- 房间准备阶段支持 GitHub 下载、局域网来源／房主中转，或仅在本机以一姬替代。随机结果冻结，并等待真人资源确认后开局。
- 缺失资源的本机替代不修改其他玩家实际使用的角色身份。
- **新增角色或新增皮肤仍要发布新 APK**：可信目录与房间白名单随客户端发布，目前没有远程发现全新目录的热更新功能。

以下是已经实现的状态，不要按早期截图把它们改回去：

- 宿舍和资源列表中的下载绿色对勾已经按用户后续要求去除。
- “未下载”等使用游戏字体；按钮使用“部分下载”，不再用缺字的“推荐下载”。
- 聊天表情恢复较细的原版切片边框。
- 资源工具栏按钮统一宽度；独立弹窗和设置页分别适配，设置页完整显示四行角色。
- 删除资源标题下方冗余说明；独立窗口的底部说明和关闭按钮共用底栏。
- 从角色头像进入资源页时定位对应条目；加粗的定位描边与滚动条留出独立间距。关闭、退出设置或切换页签后清除描边。
- 全角色排序按每行八张头像换行，支持滚动、拖动排序、边缘滚动，末页角色可达。
- 排序窗口完全遮住的宿舍头像不再继续刷新，避免占用缓存；入退场期间仍保留背景过渡。

资源加载策略：

- 新包采用 LZ4，旧 LZMA 包保留兼容。
- 安装或启动校验完成后释放临时 bundle，不把 120 个可选角色全部常驻内存。
- `CharacterPackService` 使用 **192 MiB／32 个 bundle 的软缓存上限**；当前帧可见、当前角色、宿舍角色以及被对局／传输引用的资源会保留。因此一帧显示大量头像时，数量可临时超过 32，不要据此直接判定泄漏。
- 全角色排序回归检查上限为可见网格及当前角色，并实际确认上一页未引用头像会被释放。
- 动态绘制缓存目标为四套历史服饰，编辑器校验和运行时采用相应的对象释放方式。

5. 大型新增原始媒体没有全部放进 Git 历史。角色运行包在 Release，源码中保留输入快照和准备工具。新克隆缺少本地验证包时可以主动恢复缓存，不能将“为开发恢复缺失缓存”和“发布后反复回下载校验”混为一谈。
6. 发布资源要保留旧 ID、key 和旧地址；新包使用新角色包版本／内容 tag。Android 和 Windows 分别构建与验证，不能混用。
7. GitHub 上传曾出现临时 500 和 SSL EOF。应复用草稿 ID／已上传附件，不要因 tag 查询 404 就直接创建第二份草稿。项目发布脚本已保存草稿 ID；`build/release-067/resume-publication.py` 是本轮网络重试辅助文件，不属于正式源码入口。
8. 不重新下载已发布的 APK、源码 ZIP、发布 ZIP 或角色包来重复做上传验证。优先用本地完整性／签名、服务端大小／摘要和远端 Git 提交核对；实际功能测试或缺失缓存恢复另按任务需要进行。
9. 发布保持原证书，检查 v1、v2 和 **API23 独立 v1**，不能只看默认验证。还要检查发布 ZIP 内 APK 与最终 APK 一致、16 KB 对齐，以及离线引擎已同步。
10. 不要将 SDK、工具、缓存、玩家状态、密钥、凭据和原始参考 APK 提交到 GitHub；继续使用明确清单整理 `.publish`，不要直接把开发工程所有未跟踪文件全部提交。

## 10. 下一位接手者的起点
