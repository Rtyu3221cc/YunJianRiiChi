5. 牌局生命周期：最终交互约定

触发行为
终局“下一局”按钮显示“下一局(9)”逐秒至“下一局(0)”，9 秒后自动确认；保留房间设置、玩家及座位，所有真人确认或处于托管时推进下一整场，无需房主再次按开始。等待其他真人时避免重复发起请求。
终局“返回大厅”离开当前牌桌回大厅。房主结束整桌；其他真人主动退出后电脑接替该座位，原离桌者放弃其回座凭据。
牌桌退出按钮中弹窗确认。房主提示退出会结束整桌；客人提示电脑接替。执行成功直接返回大厅；取消继续游戏。
意外关闭 / 断线不等同于主动退出；保存原连接地址、房间标识和座位凭据，允许原玩家重新连接回到原座位。无需用户输入恢复码。
三个场入口 / “牌局”灯笼统一先查询未结牌局。提示三行：“当前有未结的对局” / “（友人场-东1局 房间号xxxxx）” / “是否继续牌局？”。括号内容取真实场次、局数、房间号；“继续牌局”右黄色，“退出牌局”左深色。
继续牌局用原连接和座位身份恢复；成功后收回托管，并重播既有进入牌桌转场。查询本身不发送在线心跳，不能把大厅用户误判为已回桌。
大厅主动退出未结牌局执行离桌后进入创建 / 加入房间界面。删除旧“已有房间，请先在房间内结束牌桌”阻断弹窗。
无进行中牌局中弹窗：“当前无进行中的牌局”。房间失效 / 无法恢复远端连接时：“牌局已取消，期待下次相遇”。本机房主服务暂未就绪单独提示重试，避免误清本机练习记录。
180 秒未操作服务端按单次合法操作等待计时，达 180 秒开启 AI 托管。普通轮询不能自动关闭托管，也不能把连续多个短等待累计成一次超时。
断线 / 前后台心跳超过约 12 秒或应用主动报告离开前台后，原座位可托管；保留其返回资格。房主本机 Service 尽量后台继续运行。
左下 AI托管原工具列位置改为 AI托管，复用原 ON/OFF 菱形按钮和原版文字底托。可手动开启 / 关闭，关闭或成功回座后由真人操作。
中途加入人机局可替换真正的电脑位，继承该位当前手牌、分数、庄位与牌河，不重新发牌；不能抢占为断线真人保留的座位。

联机不要求房主开热点。同一允许设备互访的局域网即可：UDP 8766 按房间号发现，HTTP 8765 加入与状态交互。广播受隔离时可使用连接设置中的房主地址。只输入房间号不是互联网跨网房间服务。

没有房主迁移机制；系统强制停止房主进程时，其他设备需要等待房主服务恢复。所有真人离线时在结算处等待，不应无人值守反复开整场。AI 的决策输入仍为目标座位自己的可见视图，不应暴露他人暗牌。

  4. apksigner --min-sdk-version 23 验证 v1 + v2，再用 --min-sdk-version 23 --max-sdk-version 23 独立验证 v1。minSdk 26 下默认验证会跳过 v1，不能只看默认输出。

  6. 推送 main 后用 git ls-remote 核验远端 commit，并独立读取远端 README / 关键源码证明内容存在。
  7. 新文件名完整下载 GitHub APK；遇部分下载显式 Range 续传，完成后再次检查长度、hash、ZIP、v1 / v2、独立 v1、证书及 16KB 对齐。不得把截断包描述为签名失效。

11. 新对话应如何继续

  1. 先确认用户要继续的新目标，读取本 HTML、README 最新段落、本版验证记录；检查两个 checkout 的当前状态，不清理未知改动。
