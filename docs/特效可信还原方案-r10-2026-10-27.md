# 特效可信还原方案与本轮核查

本轮交付源码修正、动作验证视频和资源／兼容性审计，不生成新 APK。现有 `0.6.14.apk` 保持原文件，不会自动包含本轮修改。用户已选择：先隐藏改编试装，集中修复原版资源。

## 结论

问题包含适配层的明确错误、改编效果与原版的混淆，以及验证标准不足。资源层数齐全、能看到粒子、能打包，只能证明部分完整性，不能证明动作和画面等价。后续验收以原始播放规则、原材质实际启用的功能、原渲染程序和独立参考输出为依据。

### 幻影方向

旧实现把特效根的 `forward (+Z)` 当作牌的正面。通过原网页牌模型与 APK 牌模型的正面 UV 基向量核对，Z 反射后的原模型正面为 **−Z**，其 UV 向上方向应沿本项目牌面的长边正向。

由两个模型计算的挂接矩阵为 `[[1,0,0],[0,0,-1],[0,1,0]]`，对应 +90° X；旧 −90° X 将长边方向反转。现在从 `source-tile-frame.json` 读取推导结果，并按原网页模型宽度换算，不再只检查一个假定的法线。

实际完整宣言流程中，人手幻影主移动段的拖影方向与牌运动方向点积约为 **−0.9958**，四个观察视角一致。这个检查针对实际移动轨迹；源 UV、正面与原模型尺寸另有独立数据核查。

### 飞羽动作

已核对的**原网页代码**明确按立直资源 `sargs` 分支选择动作：`shu` 或空参数使用 `Dapai`，横向牌面特效使用 `LiQiPai`。飞羽配置为 `shu`。因此本轮没有擅自把飞羽换成长版 `LiQiPai` 动作。

旧预览只触发宣言出牌，没有接后续放立直棒；地面分支也未完整采用 `Dapai` 的原速度与关键点。现在从原动画表生成 20 条动作合约和 6 条立直绑定，完整预览使用“宣言出牌 → 宣言成立 → 放立直棒”的公开事件链。等待窗口在演示中压缩并注明。

例如人手 Dapai 的 speed 为约 0.94，触发和释放点均为 `319 / speed` 毫秒；LiQiPai 的触发点为 0.275 秒、释放点为 0.65 秒。释放点采用原配置关键点，不再用烘焙顶点停止移动的时刻估算。

这些结论来自缓存的原网页代码／配置；尚未证明它与所给 Android 客户端完全同版本，不能据此宣布原生端所有细节一致。

### 材质核查的边界

不能仅凭 Shader 名称不同，就断言所有显示差异都由 Shader 引起。进一步核查表明，当前七个 FizzFX 材质实际上主要启用主纹理、颜色、Alpha 和 UV 滚动；旧导入已将这些颜色／Alpha／滚动速度映射进 Tint 和滚动参数，字段检查相符。多个其他纹理槽目前为空，不能当作实际丢失纹理计数。

仍需验证实际着色公式、采样设置、深度与排序、全局质量设置及时间基准。例如原程序使用全局 `_Time.y`，现有滚动路径使用特效年龄。字段相符不等于最终像素已等价。 recovered GLES 程序与“仅有属性表的 Shader 导出”也已分开保存，后者不能当可编译源码。

## 已查出的统一兼容缺口

审计当前 17 个网页转换图后，发现樱花与旋风中的花瓣／叶片启用了**三轴角速度**，当前转换只处理标量角速度。这同时影响相应和牌资源与改编鸣牌。此前“全部层数已经搬过来”的检查没有覆盖这个语义缺口。

本轮加入导入准入检查：未支持的三轴角速度、动画控制组件、部分曲线／单行图集等功能会明确拒绝导入，避免静默降级后输出“完整导入”。这不表示三轴角速度已经实现；它被列为明确缺口。

樱花、冰晶、风涡与蝙蝠鸣牌均为跨类别改编试装，当前核对配置中没有对应的原版鸣牌项。已从默认选择列表隐藏，旧 ID 保留，保证旧配置和已冻结的对局仍可解析。

## 采用的后续路线

1. **原生资源优先。** 为四款原生鸣牌建立独立参考场景，保留原尺寸、节点、模块、材质全部字段与采样信息。坐标换算集中在场景根或相机映射，避免逐层修改大小、速度和周期来适配。
2. **按实际功能恢复材质。** 两个 Legacy 粒子材质家族与 FizzFX 分别验证。原始 Android 着色资源在目标平台验证加载；需要移植时，对照已恢复的 GLES 运算及实际启用功能实现，不统一替换后宣称相同。Unity 的 AssetBundle 包含平台相关内容，加载与渲染需要在实际平台验证：[Unity 官方说明](https://docs.unity.com/en-us/engine/6000.0/manual/assets-and-media/assets-managing-runtime/assetbundles-section/asset-bundles-intro)。
3. **播放规则形成可追溯合约。** 动作名、speed、lifetime、关键点、挂接模型、地面／跟牌、释放与销毁规则来自同版本源配置和代码。无法确认的控制器明确标记待支持，不能用一个通用分支替代。
4. **建立独立参考回放。** 使用原始数据与原渲染程序的参考路径，固定种子、时刻、相机、材质时间和质量设置；与本项目路径对比。先覆盖渲染模式、三轴旋转、图集、UV 动画、混合与挂接这些功能组合，再自动批量回归所有注册效果。这样不需要用户逐款提供录像，也避免拿导入代码自己生成的预期值给自己背书。
5. **通过准入再开放。** 数据完整性、功能覆盖、几何／时序和参考画面分开报告。当前优先做原生鸣牌参考与 FizzFX 对照，不再扩充改编装扮。

完整的原生参考渲染／材质兼容后端**尚未完成**；以上为有实际资源证据支撑的实施路线，不是已经实现完全还原的声明。

- `build/wardrobe-r10-study/`：源代码片段、原材质、GLES 程序、审计与验证记录。
