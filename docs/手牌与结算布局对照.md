# 手牌与结算布局对照：Unity 0.5.17

对照源：用户提供的 937×431 牌桌、934×430 和 774×438 结算截图，以及本地雀魂 Majsoul_4.0.16_MC.apk 提取的 UI_Win 和手牌相机数据。参考中的皮肤立绘保持替换为一姬。实际工程使用 Unity 的渲染/GUI 适配，坐标取自预制体，不宣称复制完整 APK 脚本运行时。

| 原版预制体数据 | 修正 |
| --- | --- |
| hand camera size 9、quad 高 2.54 | 手牌高约为安全区高度的 14.1%，副露不会迫使缩小手牌 |
| container_hand (-251.6,275.9)、.96 缩放、6 度；tile 80×120 | 牌列向左上恢复，原麻将面/背、0.62 比例；杠牌过多时仅让结算牌列适配其可用宽度 |
| container_dora (27.5,250)、lidora (536.5,303)、.7 缩放 | 宝牌行和里宝牌行跟随牌列斜向排布，使用实战牌面/牌背 |
| container_fan_8、container_fan_yiman 子项原坐标 | 少量役种先纵向排列；役满名称不附加普通 1 番字样 |

宽屏背景单独延伸到安全区两侧；内容按原设计画布的中心锚点等比适配，避免把所有内容按宽度放大造成上下裁切。原版 Btn_common 的按钮风格保持。

回归使用 1280×720、1688×780、2760×1256、844×390，以及与用户结算截图一致的 934×430、774×438。截图来自实际 Unity 客户端的合成公开状态场景，未安装到安卓真机。检测覆盖手牌固定高度、裁切、公开副露/拔北遮挡、选牌抬起、原色手牌、整模型蓝色、结算面背一致性、暗杠、五宝牌、六位点数、长标题及双荣和阶段。

## Unity 0.5.18 名称倾角与两处间隔

原版 UI_Win/scaler_width/root/container_name/container_name 的 RectTransform 旋转 quaternion.z=0.04142316058、w=0.99914169312，换算约 4.748 度。玩家名称在 Unity GUI 中以 -4.748 度旋转，名牌背景使用原图，不重复旋转位图。

牌列按照手牌、全部副露、和牌三个段落排列。有副露时只在手牌/副露交界和副露/和牌交界分别留半个牌位的大间隔，多组副露之间没有间隔；无副露时只有手牌/和牌间隔。牌框宽度等于步长，高度按实战 HandWidth/HandHeight=.62 换算，解决旧版 1 像素缩窄和 1.5 高度比产生的组内留白。原位图和牌背、暗杠端点处理保持。

实际 Unity 774×438 参考场景改为七张手牌、两组三张副露、一张和牌，核对只有两个大间隔。934×430 无副露、1688×780/844×390 暗杠及五宝牌场景同时核对倾斜名称、连续组内排列和末尾和牌空间。
