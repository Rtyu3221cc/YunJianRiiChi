# 退出、回座、续局与 AI 托管 · 本地审阅

本轮按新需求修改牌桌的会话生命周期；不提交 Git，不构建 APK，不运行单元测试。既有出牌、鸣牌、算分和 AI 决策算法保持原样。新增弹窗统一复用“食断”说明的 852.3 × 510 逻辑尺寸、背景、边框、装饰、确认按钮及 `ui_pop` / `ui_popout` 动画。

## 终局

“确认”改为“下一局(9)”，每秒递减到“下一局(0)”，到零自动确认。确认后等待其他真人；所有真人确认或处于托管后，由服务端推进，无需房主再按第二次。保留房间号、三／四人、东风／半庄、赤牌、场次类别、玩家和座位，重新开始一场。按“返回大厅”则执行离桌：房主结束整桌，其他玩家的座位转为电脑。普通小局的结算确认也由同一服务端准备机制推进。

## 回座

本地保存原连接地址、座位凭据、房间标识及展示用局数，不让用户输入恢复码。三个大厅招牌及“牌局”灯笼先查询原房间，使用同一个中弹窗显示实际场次、当前局数和房间号。查询本身不发送在线心跳，不会把处于大厅的玩家误当成已经回座。

返回牌局成功后取消该座位的托管，复用已完成的进牌桌转场。远端连接失败或原牌局不存在时清理本地入口并显示“牌局已取消，期待下次相遇”。本机服务短暂未就绪时保留记录并提示稍后恢复，避免把本地练习误判为网络房间取消。

主动退出经用户确认后，房主删除整桌存档；其他玩家放弃原座位凭据，电脑接替。意外关闭／断线则保留身份，重新连接仍是原座位。大厅退出未完成牌局后进入创建／加入界面。旧“已有房间，请先在房间内结束牌桌”提示改为结构化的回座入口，恢复码输入项已移除。

## 局域网与托管

不要求房主开启热点，设备在同一个允许互访的局域网即可。Android 前台房主服务在 UDP 8766 回答房间号查询，准备中和已经开始的房间均可发现；HTTP 8765 处理加入。无法广播时仍可使用连接设置中的房主地址。

已经开局也可加入，接替一个真正的电脑座位，继承它当时的手牌、分数、庄位和公开牌河，不重新发牌。不会抢占断线真人保留的座位。

单次合法操作等待 180 秒未响应，服务端开启托管；连接心跳超过 12 秒或主动报告应用离开前台时，也开启托管。普通状态轮询不会关闭托管。玩家点击左下“AI托管”切换按钮或凭原连接返回牌局时收回操作。AI 始终使用目标座位自己的公开视图做决策。

房主服务在后台继续运行，但不提供房主设备间的主机迁移；系统强制停止房主进程时其他设备需等它恢复。所有真人都离线时，牌局在结算处等待，不会无人值守地重复整场。

## 素材与验证

ON/OFF 图标复用项目已有的 `ob_ting_on_btn`、`ob_ting_off_btn`。原版文字底托 `button_text_bottom_s` 原先缺少，已从现有雀魂 APK 提取并记录到 `reference-skin.json`，没有重新绘制美术。

Java 房主插件和 Unity 脚本已进行编译检查。隔离 HTTP 房间的流程联调覆盖：已有房间改为回座入口、中途接替电脑、手动托管保持、离开后托管、服务恢复后原座位回座、客人退出、房主结束后重新建房、终局续局保留设置及玩家；实际保持在线并等待 180 秒，观察到 `autoReason=timeout`，随后关闭托管恢复真人操作。没有运行单元测试，没有连接真实手机；手机后台和多设备局域网行为仍待真机确认。

实际 Unity 客户端也已连接专用空白本地房主服务，串联完成建房、补齐电脑、开局、暂离大厅、查询未结牌局、回座（记录转场剩余 3.5 秒）、启用托管、结束整桌、查询无进行中牌局，以及重新创建四人半庄比赛场房间。联调期间显式串行操作请求，屏蔽慢速无界面渲染时的自动轮询争用；不写入正式玩家偏好和存档。

效果图与视频是 Unity 使用本地演示状态的渲染，涵盖宽屏和 16:9、中弹窗进出、原版回桌转场，以及 9→0 倒计时；审阅页另附上述实际客户端操作的截图。所有演示房间号和成绩不属于实际用户牌局。
