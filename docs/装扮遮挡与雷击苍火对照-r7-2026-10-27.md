# 装扮 R7：鸣牌遮挡、雷击序列与苍火坐标

本轮只修改源码、录制与验证视频，不生成 APK，不提交或上传 GitHub。R6 视频保留为历史对照。

## 已定位并修正的具体错误

- **鸣牌遮挡**：导入的 3D 粒子材质使用统一的 LessEqual 深度测试，可能被牌河和邻牌切掉。现在普通引导保留 LessEqual，其余鸣牌指示使用独立的 Always 材质实例和透明覆盖队列；不修改全局材质资产，也保留原 UV 滚动实例。用真正的不透明遮挡物，在六款指示、四个座位验证：普通引导被遮住，其余仍有实际像素。
- **雷击序列**：`effect_hupai_default` 的 `light` 是一列四行的序列图。旧代码只在 `tiles.x > 1` 时启用 TextureSheetAnimation，漏掉该情况，导致完整多帧贴图作为一张图被拉伸。现在任一维大于一就启用，保留四行、原帧曲线和五次循环；用烘焙 UV 验证单次只使用四分之一行高。上一轮向下速度的检查不足以发现这个错误。
- **粒子叠加数量**：旧转换始终用 Burst.max，忽略原 `_burst` 使用的独立随机通道。现在从场景恢复 autoRandomSeed、randomSeed，并复现原 Rand 的 JS 双精度运算、发射通道偏移 592910910 和正数向上取整规则。雷击的固定种子 622648896 实际产生两束，旧转换是三束，会改变叠加亮度。11 个现有 Laya 图、86 层补全了此信息，四视角实际粒子数均验证为 2。其他随机属性仍由 Unity 模拟，不宣称整套随机序列一致。
- **苍火绑定**：原牌模型使用 XY 牌面，Laya 中平放的 +90° X 经过 Z 反射对应 Unity -90° X。旧绑定使用 +90°，把主要发光层放到牌底一侧。现使用正确牌面方向，中心点随携牌旋转，并按实际牌宽换算资源单位。
- **原播放速度**：原 `ModelAnimationController.init_data` 会将 lifetime、keypoint 除以 speed。现按该规则解析人手两倍速、猫爪 1.2 倍速等参数。骨骼采样、携牌交接与特效触发共同使用解析后的时间，不再只按原始文件长度播放。人手触发点为 0.275 秒、动作结束 0.8075 秒。

这些属于可修正的实现遗漏。之前的“粒子存在”“速度向下”“曲线导入”等检查不能替代视觉一致性核对，不应据此宣称完整还原。

## 为什么仍难以保证逐款完全一致

当前提供的基础 APK 中有 Unity 原生鸣牌预制资源，但没有本次所需和牌／立直的原生预制资源。后者采用缓存的网页版 Laya 场景、材质、网格和动画转入 Unity，因此需要重建两套引擎的模拟、坐标、粒子几何、贴图序列、混合、深度和绑定语义。

另外，原 APK 的部分 Lua 受保护，着色器主要是 Android 编译数据，桌面预览使用适配着色器；缓存的网页资源版本与原包也未证明完全对应。即使资产参数相同，随机数、摄像机、颜色空间及后处理仍可能产生差异。视频提供二维结果，无法补全被挡住的层级、材质状态或完整动画规则。

主要需要改进的是导入兼容层和验证方法，用户无需先升级硬件或为每款继续录像。最有帮助的补充是**与参考客户端同版本的完整热更新资源／缓存及其配置索引**，包含特效预制体或场景、材质与着色器数据、纹理图集、网格和动画。若有可解析的原着色器源码更好；普通玩家通常没有这些源码，完整缓存仍有价值。单个 APK 可能只含基础资源。
