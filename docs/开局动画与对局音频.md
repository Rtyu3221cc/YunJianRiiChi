# 开局动画与对局音频（Unity 0.5.21）

参考用户录像 `开局整理手牌.mp4` 和 `打牌时的背景音乐以及出牌音效.mp4`。原版 `ViewPlayer_Me.NewGame` 每 300ms 增加至多四张牌，`AnimNewTile` 用 200ms 淡入并下降，1200ms 调用 `LiPai`；`HandPaiPlane.Update` 以每秒 25 个牌宽将牌滑向排序后的位置。本项目保留自身原始发牌顺序和实际摸牌，不使用随机展示牌，不更改出牌索引或规则。

| 时刻 | 手牌表现 |
| --- | --- |
| 0 / 0.3 / 0.6 / 0.9 秒 | 分组发出四张牌，最后一组包含余下的牌；200ms 淡入并落下 |
| 1.2 秒 | 按万、筒、索、字顺序横向滑动整理，庄家最后一张摸牌保持独立 |
| 最迟 1.76 秒 | 整理结束；牌位、大小及操作恢复为普通手牌 |

`handSeq` 标识本局，`dealtAt` 排除超过 2.5 秒的开局历史。`openingHand` 仅包含接收者自身的初始牌；其他玩家的牌和发牌顺序不进入 `PlayerView`。动画期间输入不会提交出牌。轮询重建模型时继续原进度；若 AI 的首张出牌让非庄家提前摸到第十四张，仍整理原来的十三张牌，结束后显示实际摸牌，不中断或重播。返回大厅、后台暂停或其他牌状态不再吻合时取消并恢复牌面。

资源：`newround_pais`、`discard_tile`、`fulu`、`put_liqi`、`zimo` 从用户提供的雀魂 4.0.16 APK 的 AudioClip 导出。默认 `game.mp3` 未在本地 APK 音频目录中找到，使用雀魂官方固定版本资源 `https://game.maj-soul.com/1/v0.10.275.w/audio/music/game.mp3` 补充。它与录像前四秒音轨的归一化波形相关度 0.96244，对应原曲 9.345 秒位置；另一首 `game_master.mp3` 相关度仅 0.09184。运行时无需网络获取音频。

音乐、角色语音和桌面音效各用独立 AudioSource；BGM 以流式加载循环，轮询不重启。落牌等声音只在 `TableEffects.CompleteHandoff` 首次交接时播放，避免在后台收到状态时提前响或反复响。发牌声音与四组发牌节拍同步。后台暂停音乐和音效，回前台续播音乐，不补播历史落牌；返回大厅停止。声音设置各有开关和音量，并保存偏好。

资源出处和 SHA-256 记录于 `unity/Assets/Resources/Majsoul/Audio/provenance.json`；`scripts/import-table-audio.py` 可重导五项 APK 音效并核对原版音乐哈希。完整 Unity Play 实测分批数、淡入、滑动、最终位置、轮询/重连、取消恢复、输入锁定、声音交接、循环/静音/暂停/续播；既有手牌、副露、听牌、振听、流局和结算回归同时通过。自动化使用合成公开状态截图，未执行安卓真机安装、听感与热点联机验证。
