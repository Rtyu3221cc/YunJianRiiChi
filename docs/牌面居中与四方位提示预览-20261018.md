## 用户指出文字形变后的修正

根因是导出紧边图片后丢失原始 Sprite 留白，而非五种字图本来就采用不同的 UI 宽高。APK 内五张原始 `Sprite.m_Rect` 均为 187×143；UnityPy 的 `Sprite.image` 按 `textureRect` 裁切后分别成为吃 142×143、碰 156×132、杠 142×138、立直 187×105、拔北 187×104。上一版把这些裁图铺满节点，造成单字拉宽、双字在竖向撑高。

APK `global-metadata.dat` 直接确认 `capsui.CImage.FixImage`（方法 token `0x06002b27`）以及枚举 `EnumFixMode`：NONE=0、FORCE_KEEP_WIDTH=1、FORCE_KEEP_HEIGHT=2。四个 `img_content` 节点的 `CImage.FixMode` 均为 1。Lua 层另有 `ui_desktopinfo.lua.bytes` 与 builder；它们是脚本字节码。当前证据区分 APK 编译代码元数据、预制体配置，以及之前缓存的官方网页静态 JavaScript；不将元数据或网页片段冒称为 APK 的 C# 源码。

`import-callouts-1018.py` 现从 APK 原图集完整取 `m_Rect`，将五张含原始透明边距的图片单独保存到 `Callouts1018`，不修改其他界面的旧 `Actions` 字图。运行时读取 FixMode 并按原始画布比例保持宽度。`NativeCalloutAssetImport` 保留 NPOT 原尺寸，防止 Unity 默认把 187×143 导入为 256×128；预览入口验证五张实际导入尺寸均为 187×143。

Sprite 完整坐标及紧边偏移在 `Callouts1018/word-sprites.json`；元数据字段、枚举常量、方法 token 和读取脚本保存在 `build/review-1018/reference/*-metadata.json`、`image-component-metadata.txt` 及 `parse_image_component.py`。旧字图预览备份在 `build/review-1018/text-fix-baseline`。最终预览仍只输出实际 Unity 画面及视频。

## 四个方向文字统一大小

用户明确要求四方向字号一致。前版文字随整个角色横幅缩放，且四套文字节点原始宽度分别为自家250、右家211、对家187、左家211。与方位倍率相乘后，设计坐标中的有效宽度分别为137.5、105.5、91.63、101.28，自家明显偏大。

现将文字从角色／背景合成层中分离，保留每个方位的原文字中心、入场位移和透明度；五张完整字图统一用104个设计像素宽，按187:143等比绘制。角色和背景的已审阅方位布局保留；文字不再继承其字号差异。相同分辨率下，同一种提示在四个方向使用相同的屏幕绘制尺寸。

预览在真实GUI矩阵变换后记录 `word-metrics.json`：1688×780的五种文字各四方向，以及1280×720的立直四方向。打包时核对宽高差小于0.001像素；等倍率局部图全部从实际截图取200×160原像素，统一放大两倍，不按各自字体大小缩放裁图。原荣和、自摸预制体各四方向均为726×295，当前路径本来就统一尺寸，未修改。

当前轮源码备份在 `build/review-1018/uniform-word-baseline`。仍仅编译并渲染预览，不构建APK或发布。

## 统一每个字的大小，双字自然增加宽度

用户进一步明确，“立直、拔北”不能与单字提示共用相同总宽度。前一版104设计像素的整图宽度规则已移除，现统一字形的可见高度为80设计像素。以原PNG透明通道中alpha≥8的包围框衡量字高，整张原图做等比缩放，因此双字提示自然约为单字“吃”的1.9倍宽，而每个字的高度一致。

完整Sprite画布与原透明留白仍保留；仅计算显示比例，并以可见字形中心对准各方向已有文字锚点，不横向拉伸、不裁掉笔画。相同提示在四方向维持同样大小，人物与背景布局保留。

`word-sprites.json` 新增inkBounds及字数记录，资源来源哈希随导入脚本同步更新。实际GUI绘制记录新增可见字形的屏幕宽高；打包核对五种提示的可见高度一致、同一提示四方向尺寸一致，并检查双字总宽度明显大于单字。当前轮源码备份在 `build/review-1018/character-size-baseline`。
