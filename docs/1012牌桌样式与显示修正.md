# 1012 牌桌样式与显示修正（Unity 0.5.26）

只修改 `D:\MyWorkSpace\YunJianRiichi_Codex`，参考 `D:\MyWorkSpace\video\1012-1` 四张批注图片。

1. **姓名与房间样式**：姓名使用 APK 的 `bg_name_1` 和 `SimHei` 字体，配灰色称号、分隔纹饰。显示各玩家真实姓名，默认称号为“暂无称号”。房间文字采用原版毛笔字体，按人数／局制显示“铜之间 · 三人东／四人东／三人南／四人南”。使用原图 `hint` 的菱形感叹号，移除左侧出牌提示按钮及文字；感叹号只在自身听牌、或自己的出牌回合有打出后听牌的合法选择时出现，保留长按查看待牌。
2. **指示牌反光**：指示牌本身只有是红五、或由另一张指示牌指出的实际宝牌时才反光。盖住的牌不亮。标准日麻的指示牌 6 筒对应宝牌 7 筒，计分规则没有倒置；[WRC 官方规则 8.13](https://www.worldriichi.org/s/WRC_Rules_2022_20220708_site.pdf)同样规定同花色的下一张。
3. **副露位置与方向**：旧避让把自家副露抬到手牌上方；现在按实际安全区、牌面投影及手牌底边定位到右下角，并给手牌让出横向空间。上、右、左方保留各自的副露累积方向，自家新组向左累积。三种杠的既有交接继续使用原组和第四张目标；动画期间的投影测量使用静止位置，避免布局跟着搬运目标抖动。
4. **终局比例**：缩小头像视口、姓名、排名和点数字图，保留原背景框比例；恢复绿色 `+0.0`、金币与 PT 图标及 `+0`，这些值按用户要求固定显示，不新增段位／奖励计分。
5. **对家立直穿模**：出牌和立直搬运对象的原骨骼关键点未与实际牌河目标对齐，导致交接前落在另一行，交接时跳回正确位置。现在从整个手部变换减去落地关键点偏移，搬运牌与静态牌的位置和旋转一致；覆盖两行牌河的对家立直检查。
6. **反光降低 15%**：反光 RGB 统一乘 0.85，保留透明度、循环速度、原始贴图和 UV；手牌的隐藏、淡入和不可选变暗继续传给反光。
7. **对手牌河清晰度**：所有座位共用同一组原牌面图，未发现另用低清美术。透视缩小、斜视和 mip 选择使远端更模糊；启用 16 倍各向异性、三线性采样和轻微负 mip 偏移，并提供同局面的采样前后图。

牌河加入幅度很小的位置／角度错落。以公开座位、原始弃牌序号和局数生成稳定扰动，轮询、鸣走别人的牌和观察方向切换不会重新随机。六张一行、立直横牌和被鸣牌移除仍由原公开数据决定。相关 APK Lua 脚本仍加密，本次没有恢复可直接抄用的原牌河随机代码；这是对参考摆放的适配，不能声称逐字复制雀魂实现。

原贴图和姓名字体记录在 `TablePolish/source.json`，含 bundle、pathID 和 SHA-256；既有粒子资源继续由 `NativeReview` 提供。

验证：81 项规则／协议测试通过；实际 Unity Play 检查菱形按钮出现条件及长按、指示牌是否为宝牌、0.85 亮度、自家 1～4 组副露在三种尺寸的底边与横向间距、吃／杠动画衔接、牌河扰动稳定性、两行牌河立直落地、纹理采样与三／四人终局。图片是合成公开局面，未进行安卓真机触摸、热点联机或实体设备听感验证。
