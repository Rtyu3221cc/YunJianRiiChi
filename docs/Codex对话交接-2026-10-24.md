## 5. 后续特效开发的现有代码地图

### 5.1 事件与呈现链路

维护源房间引擎提交公开动作，产生 `audioRoom / audioSeq / audioEvents`；客户端应用房间状态后调用 `TableEffects.Accept`，再由手部队列、喊话队列和粒子/切入组件呈现。

`PublicSound` 包含 `id / seat / kind / tile / riichi / nuki / from / riverIndex / meld / meldKind / meldIndex / winSource`。这些是已提交的公开信息；特效不能读取对手暗手来推测动作或驱动显示。

关键行为：

- `TableEffects` 维护房间和事件游标；新房间首先建立基线，重复轮询不重播。间隔超过八秒的陈旧动作会跳过，不补播整串旧动画。
- 手部动作和喊话是独立通道，立直喊话可以与出牌手部动作同时播放。
- 真实牌、立直棒、副露、拔北牌和移动替身有交接点。改变时序时必须同时检查显示/隐藏和最终状态，防止重影或牌消失。
- 和牌动作、切入、和牌粒子与结算面板有先后关系。不要在手部/牌张特效尚未交接时提前展示结算。
- `RiichiDiscardVisual` 的本局去重账本跨呈现重置和手机暂停保留；新手牌才清除。不要为了重播测试特效而破坏生产去重行为。
- 新增纯装饰事件需要服务端同步时，可参考表情的独立序列模式，避免无意义地改变出牌版本或影响规则。

### 5.3 特效开发不能忽略的约束

1. **先查实际调用路径。** 例如当前和/自摸字图来自 `Presentation0535`；其他目录存在同名素材，不应只改某个同名文件就认为生效。
2. **四向映射按组件确认。** `NativeCallouts`、`NativeAnnouncements`、人物构图的 slot 约定不同，不能把同一个索引表直接套给所有界面。覆盖三人、四人和自身/各对手方向。
3. **保留透明画布与原始比例。** 注意 TextureImporter 的 NPOT 缩放、最大尺寸、Wrap、Mipmaps 和 Android 平台覆盖值。既有和/自摸拉伸问题已修正，不要回退。
4. **按原模块恢复粒子。** 保留层级、位置、旋转、缩放、Emission/Burst、Shape、Color/Size 曲线、材质混合方式和排序；不要只提取一张 PNG 后凭感觉猜动画。
5. **区分编辑器和手机 Shader。** `NativeParticleEffect` 使用原 APK Shader 的分支仅在 Android Player 执行，编辑器回退效果不等于手机 Shader 已验证。新增运行时创建的 Shader 要核对 `ProjectSetup.Configure` 的 Always Included 列表或明确的 Resources 引用。
6. **管理相机、层级和透明合成。** 注意当前 layer 28/29 的用途，保存/恢复 `RenderTexture.active`、GUI 矩阵和颜色，处理 PMA/直通 Alpha 及 Additive 叠加；尾光不要被过小的 UI 视口裁掉。
7. **加载与释放都要有设计。** 新可下载特效避免在 OnGUI/点击入口同步打开大包、解码大纹理或加载全部对象；优先复用异步队列、预热、缓存和必要的过渡。切房间、换局、退出、跳过和组件销毁时释放 RenderTexture、Material、Mesh、ParticleSystem 和相机。
