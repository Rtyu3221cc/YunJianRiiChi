# 拖动出牌 R17

日期：2026-10-28。随 Unity 0.6.17（versionCode 65）进入实机测试包。

## 操作

- 按住手牌后移动，实际那张牌随手指自由拖动，原位置暂留空位。
- 松手位于牌桌中央区域，且当前仍可合法打出该牌时，提交出牌；立直选牌模式提交对应的立直出牌。
- 拖回手牌附近、拖到牌桌边缘松手，或触摸丢失、出现第二根手指、切后台、失焦时取消，不会误当成第二次点选。
- 原有“点一次选牌，再点同一张出牌”保留。拖动未发生时仍沿用这条规则。
- 状态轮询不会换成另一张同种牌，也不会将拖动中的牌移回手牌。轮询正在进行时松手，短暂等待结果后重新核对同一次决策；超过 1.5 秒、局面变化或新操作会取消，不会在很久后突然出牌。

## APK 核对结果

在用户本机 `dist/Majsoul_4.0.16_MC.apk` 的资源容器中找到了：

```text
luabyte/lua/game/mj/handpaiplane.lua.bytes
luabyte/lua/game/mj/handpai3d.lua.bytes
luabyte/lua/game/mj/viewplayer_me.lua.bytes
luabyte/lua/game/mj/hand.lua.bytes
luabyte/lua/game/mj/mjpai.lua.bytes
```

这些 TextAsset 是 Base64 包装的保护载荷，解码后也不是标准 Lua／LuaJIT 字节码头。本轮没有恢复可读的原版拖动函数，不能据此声称已经取得原版阈值。提取文件、尺寸和 SHA-256 保存在 `build/drag-discard-r17/reference/`；这些本地研究输入不加入运行时资源或发布附件。

当前交互是按本轮用户描述实现的适配：位移超过手牌高度的 10%（最低 8 屏幕像素）进入拖动；出牌区域水平位于安全区域中央 76%，下边界高于手牌，上边界覆盖牌桌中央。区域根据手牌的实际投影、安全区和桌心位置计算。它不是从原版脚本中直接抄取的数值。

## 代码与验证

- `RiichiClient.HandDrag.cs`：指针捕获、拖动与点选区分、决策标识、松手区域、轮询等待、取消。
- `TableRenderer.cs`：在相机布局完成后恢复拖动位置，保留按下位置与牌中心的偏移。
- `RiichiClient.cs`、`RiichiClient.Session.cs`：接入原有合法操作通道，生命周期取消和轮询重建。
- `DragDiscardR17Preview.cs`：真实 Unity 输入入口和牌模型检查，测试期间拦截操作提交，不操作手机或真实牌局。

177 项运行检查通过，覆盖 1280×720、1746×810、2340×1080，含异形屏安全区域；检查了真实模型跟随、拖回归位、重复牌、拖动中轮询、轮询中松手、慢轮询超时、多指、失焦、局面切换、他家回合、立直选牌合法性以及二次点选保留。

另重新通过 571 项原有 Unity 单元检查、58 项听牌／头像框／滚动交互检查。实机触控、拖动区域手感、GPU 和热点联机仍由本轮手机测试确认。
