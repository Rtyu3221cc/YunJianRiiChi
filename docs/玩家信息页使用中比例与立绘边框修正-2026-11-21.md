# 玩家信息页 R7：使用中比例与立绘边框

执行日期：2026-11-21，东京时间。处理用户最新两张截图指出的使用中标记变形、立绘框显示差异。

## 原因与修正

- `Native/using.png` 是原版 130×99 图片，但旧 NPOT Nearest 导入为 128×128。ScaleToFit 因而依据方形纹理绘制，标记被横向压缩。本轮设置 NPOT None、关闭 mipmap，保持原图字节和 GUID；继续使用原预制体的 151×115 显示框，不对图片单独缩放宽高。相同 1920×1080 截图中绿色可见范围从 103×99 恢复为 135×100。
- `Native/illustFrame.png` 原图 120×120，旧导入改为 128×128；代码仍按原图 50 像素边框取九宫格 UV，导致转角采样变化。恢复 120×120 和原始采样，保留 50／50／50／50 九宫格、464×976 外框尺寸。`illustBg.png` 同样禁用 NPOT 与 mipmap，从 256×512 恢复原始 304×650，保留 450×962 显示框。
- 原预制体节点 16 的 Image + Mask 使用 `ui/common/main/pic/waitingroom_mask`，显示区域 448×957；旧实现只有矩形 GUI.Group，立绘底角会透出边框。本轮从 APK 原图集提取同一 100×100 遮罩及 36／37／37／34 边框，按九宫格映射它的非零 alpha 轮廓，合并成 24 个矩形裁切区缓存后绘制。保留原角色立绘与 CharacterFraming 的定位，不使用手绘轮廓，也不修改公共 CharacterFraming。

源资料为《點擊進入玩家信息.mp4》及本机 `dist/Majsoul_4.0.16_MC.apk` 的 UI_PlayerInfo 节点 15、16、20 和 UI_TitleBook 的 using 节点。遮罩、边框和底图原字节、Sprite 路径、bundle、pathId、border 记录在 `unity/Assets/Resources/Majsoul/Profile/native-art.json`。遮罩原 PNG SHA-256：`23ec26032d238e496e43a833d29a7633ce4a192f5022d73764317ce127e9ae81`。
