# 0.5.33 安装包签名与下载复核

用户从GitHub APK直链安装0.5.33时再次收到“解析失败：安装包没有签名文件”。本次检查完整本地包及从GitHub完整下载的包，均包含 `META-INF/MANIFEST.MF`、`ANDROIDD.SF`、`ANDROIDD.RSA`，v1、v2及强制API 23的独立v1验证均通过，证书与已能覆盖安装的历史包相同。此情况与0.5.27确实缺少v1文件的情况不同，尚未取得手机上失败文件的大小或安装器日志，不能断言本次内部原因。

此前0.5.33回下载校验时，第一次只收到29,347,328字节；显式续传后才得到完整73,408,552字节，SHA-256与GitHub上传记录一致。下载不完整是需要核查的方向，目前未确认它就是用户手机上的原因。

新下载入口使用 `yunjian-riichi-unity-0.5.33-signed.apk`，以便避开旧下载文件；它与原完整0.5.33包的字节相同，属于重新核验的独立下载副本，没有更换证书或游戏资源。完整文件应为73,408,552字节，SHA-256为：

`7578D6DD1FE348DC0AC10DC8043EF2DB776B3A1DFC20B65CE1CB8A40474B0574`

已补强构建／发布检查：

- `verify-unity-apk.py` 对实际分发APK进行v1＋v2、独立v1、固定证书及16 KB对齐验证，再检查现行资源。
- `package-unity-release.py` 在打包时再次验证APK真实签名及最终SHA-256，拒绝仅有签名文件名但签名无效的包。
- `verify-apk-signature.py` 可单独检查本地APK、发布ZIP中提取的APK及GitHub回下载APK；缺少工具、缺少签名、签名错误或文件不完整都直接失败。

这次复核不代表已在用户手机上成功安装；仍需安装新下载副本后确认。
