# 0.5.27 安装包签名兼容修正

从 GitHub 实际下载的原 APK，SHA-256 为 `658BB09737F1B66EE366B86E03C85CCA1FF55E9F288FBB529A78A1FDDC2F4E49`，与之前发布的文件一致。该包的 v2 签名有效，但没有 v1/JAR 的 `META-INF/MANIFEST.MF`、`.SF` 和 `.RSA` 签名文件。用户反馈“解析失败：安装包没有签名文件”，因此补齐 v1 作为兼容处理；未取得手机安装器日志，不能仅凭该提示断定其内部原因。

修正版为 `yunjian-riichi-unity-0.5.27-signed.apk`，SHA-256：

`F13F122F2ED1D37B028B11B37B48178D4711EC35BD2214BE6719D020A44A4ED9`

游戏版本和 versionCode 保持 0.5.27 / 28。修正前后的全部非 `META-INF` 运行资源逐项比较一致。新包增加 v1，保留 v2，证书 SHA-256 均为 `D1D8E506C6D3B62E9610DCE294C07008057318FA9BAFAE702FB8B01F35F0DC2F`。

验证：

- SDK `apksigner verify --verbose --min-sdk-version 23` 同时验证 v1 和 v2；默认验证在本项目 minSdk 26 下会跳过 v1，不能仅凭默认输出判断 v1 是否存在。
- 强制 API 23 单独验证 v1，验证通过。该参数仅用于签名验证，应用 minSdk 仍为 26。
- 新包保留 16 KB 原生库对齐，ZIP 完整性、离线房间资源、ARM64／ARMv7 和 Unity 资源检查通过。
- 发布检查现在拒绝没有 v1 签名文件的旧包；Android 构建脚本会自动执行相同证书的 v1 + v2 签名及验证。

APK 使用新的下载文件名，避免继续拿到旧下载文件。GitHub 的 `unity-0.5.27` 标签仍对应原游戏代码，签名和构建流程的修正继续提交到 main。未进行用户手机上的实际安装验证。
